This app connects to an STM32 Black Pill running the app-demo firmware over USB.

To connect:

  1. Plug the board into a USB port.
  2. It should appear in the port dropdown above, marked "(STM32)" when detected automatically.
  3. Click Connect.

Once connected, use Configuration to view and change device settings, Telemetry to watch live sensor data, and Terminal for direct command-line access to the device for debugging. All three are unavailable until a device is connected — you'll see them greyed out in the menu here.

Need help? See the Help page for troubleshooting tips.

not connected

The board doesn't appear in the port dropdown

  • Check the USB cable is a data cable, not a charge-only cable.
  • Make sure the board is powered — you should see LED activity on it.
  • Try unplugging and replugging the cable, then check the dropdown again.

Connect fails or times out

  • Confirm you selected the right port — a detected STM32 board is marked "(STM32)" in the dropdown.
  • Make sure no other program (a serial monitor, another instance of this app) already has the port open.
  • Try disconnecting and reconnecting.

Connected, but no telemetry appears

  • Check the Telemetry Rate setting on the Configuration page isn't set very low.
  • Try disconnecting and reconnecting.

Changing a setting doesn't seem to do anything

  • Changes apply to the device immediately, but only persist through a power cycle after you click Save.
  • An invalid value (out of range, too long) is rejected and shown with a red outline — check for that.

The status badge shows "stale"

  • This means the device is still connected but hasn't sent telemetry recently — often just a brief pause during a Save (writing to flash takes about a second). If it doesn't clear on its own, try disconnecting and reconnecting.

Backing up and restoring settings

  • On the Terminal page, type dump to print every setting as INI text, then copy it into a file. list shows what each setting accepts.
  • Restore from INI… reads such a file back. Settings the connected firmware doesn't have — or values it rejects — are listed as skipped and the rest still apply.
  • A restore applies to the device immediately but is not written to flash. Click Save to flash — the button beside Restore, or the one on the Configuration page — to keep it. It stays greyed out until there is something unsaved.

A saved setting didn't survive a restart

  • Confirm you clicked Save after changing the value, not just changed the field — edits apply live but aren't written to flash until Save.
